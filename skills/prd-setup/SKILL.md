# PRD 环境准备

用中文带用户把 Codex、prd 和 Figma Desktop 连通。直接完成已授权的配置工作；只把登录、私密 token 填写、桌面插件导入等当前工具无法完成的步骤交给用户。每次仅给当前需要的操作，不重复整篇教程。

## 1. 先引导安装，再准备 token

- 确定用户要首次配置、检查连接还是排障；只处理对应范围。已有正常配置直接复用。
- 首次配置按 **Figma Desktop → Node.js 和 npm → Figma token → prd / MCP → Desktop Bridge → 连接验收** 推进。读取 [配置步骤](references/setup.md)，每次引导当前未完成的一步，确认完成后继续；不能一开始就让用户填 MCP 或运行 Bridge。
- **先检查并自动安装 Figma Desktop**：结合 Windows 已安装应用记录、常见安装目录中的可执行文件或运行进程判断；未运行不等于未安装。检测不到时说明“未检测到”，允许用户提供自定义路径。未安装则直接从 [Windows 安装包](https://www.figma.com/download/desktop/win) 自动下载，下载完成后启动安装，按配置步骤检查结果，再引导用户登录；不要只给下载页让用户自行寻找安装包。网页版或字体安装器不算桌面版。
- **再自动安装 Node.js 和 npm**：未安装时从用户指定的 [Node.js v24.21.0 Windows x64 MSI](https://nodejs.org/dist/v24.21.0/node-v24.21.0-x64.msi) 自动下载，下载完成后安装，保留 npm 和 PATH 安装项；按配置步骤检查架构、安装结果及 `node --version`、`npm --version`、`npx --version`。当前 Codex 未继承新 PATH 时提示重启，不能直接判为安装失败。已有可用版本则复用，不强制降级或重装。
- **然后引导获取 Figma token**：按配置步骤中的账号菜单路径逐步说明创建与保存方式。已有可用 token 则复用；只询问是否已准备好，不索取 token 内容。未准备好时留在这一步，不启动连接验收。

## 2. 配置 prd 与 MCP

- 前三步完成后才补齐 prd 与 MCP；在线安装 prd 时检查 `git --version`。报告实际 prd 路径及 MCP 是否已配置，读取配置时只输出脱敏字段，不打印 token。
- 技能目录为 `$CODEX_HOME/skills`，未设置时用 `%USERPROFILE%\.codex\skills`。检查完整的 `prd/SKILL.md` 及其引用资源，区分缺失、重复安装和当前聊天未加载。
- 按 [配置步骤](references/setup.md) 配置本地 MCP，引导用户将已准备的 token 私密填入本机配置。用户仅要求检查时，不改配置、不安装软件。

## 3. 连接并验收

- 首次配置引导用户在 Figma Desktop 文件首页进入 **Drafts（草稿）**，创建 **Design（设计）文件**，打开空白画布后在其中导入并启动 Bridge；不要笼统要求用户找一个有编辑权限的测试文件。已有本次配置的设计草稿或已连接的 Design 文件时复用，不重复创建。
- 默认使用 Bridge 当前连接的 Design 文件做只读验收，自动读取文件身份和页面，不要求用户另发链接。空白 Untitled / Page 1 也可用于此验收。
- 需要导入 Bridge 时，按配置步骤先验证 `manifest.json`，将其所在文件夹的实际绝对路径放在独立纯文本代码块中供复制，再说明粘贴到文件选择窗口地址栏、回车、选择 `manifest.json` 并打开；不能只写“上述文件”或只给可点击链接。
- 导入后明确提示：在 Plugins & widgets 的 Development 列表点击 **Figma Desktop Bridge** 这一行，等待插件窗口打开并保持开启，再继续验收；不能把导入成功当作已启动。
- 精确发现 `mcp__figma_console__figma_execute` 和 `figma_capture_screenshot` / `figma_take_screenshot`，缺失再搜索 `figma console execute screenshot`。只使用本地 `mcp__figma_console__*`，不自动换其他 Figma 服务。
- 只有新增 MCP 配置尚未加载、确需刷新工具时才提示重新加载或重启 Codex；工具已可用则直接验收。需重启时让用户保持 Figma 草稿和 Bridge 开启，恢复后说“继续 prd-setup 连接验收”即可；重新发现工具并读取当前文件，不附带索要文件链接。
- 执行只读探测，读取实际文件名、Page 和可取得的 file ID，并实际调用截图工具。用户已指定目标文件时才核对是否匹配；未指定时以当前连接文件为准。链接或 file ID 无法取得时如实说明，不虚构链接，也不因此阻断已经通过的页面读取与截图验证。工具未暴露、Bridge 未连接、权限失败和截图失败分别报告。
- 页面读取与截图均成功即完成默认连接验收，进入简短交接；不要继续索要链接、询问是否做读写验收，或把可选写入测试列为待完成条件。只读通过不代表已验证写入能力。
- 仅在用户要求读写验收时确认写入目标；用户明确指定“当前文件”即可，不必再索要链接。在独立的“连接验收”页创建含“连接成功”文字的 Frame。先检查同名页和节点，有本技能验收节点则复用；同名内容身份不明时不覆盖。不触碰业务页面。
- 写入后重新读取节点并截图，核对文字可见、截图可打开、真实链接指向目标节点。截图失败时保留已有节点，修复后重拍，不重复创建。

## 4. 仅在失败时排障

| 现象 | 下一步 |
| --- | --- |
| 找不到 prd | 核对实际安装目录和引用文件，再提示新开聊天；不要重复覆盖正常安装。 |
| 找不到执行工具 | 查服务配置、启动错误和工具发现；不要直接判定 Desktop 断开。 |
| 执行失败 | 查目标文件、Desktop Bridge、权限和原始错误。 |
| 连接全部占用 | 先识别属于 figma-console-mcp 的进程和连接。仅重启本任务实例；需清理其他任务的连接时说明中断影响并取得授权，已有明确授权则直接执行。禁止按 node/npx 名称批量结束进程。 |
| 找不到插件 manifest | 查 MCP 是否启动成功及实际插件路径，不先改端口。 |

每次修复后重做同一验收。相同错误连续两次无新证据时停止重复操作，报告实际错误和下一项所需操作；不循环重装或扩大清理范围。

## 5. 简短交接

配置完成且默认只读验收通过时，直接报告“环境配置完成，Figma 页面读取和截图验证通过”，附实际技能路径及当前文件信息；有可信链接时才附链接。只有用户要求的验收项目未执行时才列为“未验收”，不将未请求的读写测试列为阻塞项。不要把配置存在当作连接成功。

准备好后提供一个可直接复制的登录界面练习，不再只给含 `<具体需求>`、`<ID>`、`<链接>` 的占位模板。说明“想练手时，把下面这段发给我即可”，不要自动开始新需求：

```text
$prd 带我做一个简单的 PC 网页登录界面，练习从需求澄清到 Figma 原型的过程。
产品 ID：LOGIN_DEMO。
使用刚才连接验收的 Figma Design 草稿。
界面包含账号输入框、密码输入框和登录按钮。
希望演示未填写必填项、账号或密码错误，以及登录成功后的反馈。
只做界面原型，不接真实登录接口，暂不做注册、忘记密码或第三方登录。
我没有现成的参考截图，请先说明练习需要哪些准备，再用容易回答的问题带我澄清规则；需要我确认时再进入下一阶段。
```

若已取得验收草稿的真实链接，在交接示例中将“使用刚才连接验收的 Figma Design 草稿”替换成该实际链接，方便新聊天定位；未取得则保留当前草稿表述，不要求用户先补链接才能尝试。登录规则留给用户和 prd 澄清，不把示例当作已确认需求，也不绕过 prd 的参考准备与阶段评审。
日常业务阶段和评审规则读取已安装的 prd 技能；不要在本技能复制另一套流程。项目截图放在当前 workspace 的 `Knowledge`，具体索引结构由 prd 检查，不能生成假截图或空索引冒充就绪。
