# TodoList 技术验收主线

来源：用户要求先实施 Storybook 与 Plane 自动化，再用 TodoList 作为技术验收。不是正式待办产品需求；示例交互用于验证原平台的会话、范围、固定版本及交付契约。

## 技术场景与验收

- AC1：新增非空待办，空白输入给出提示；完成/取消完成、删除和全部/待完成/已完成筛选可用。输入作为文本显示。
- AC2：设置应用切换“显示已完成”，返回列表反映设置；切换应用及列表/统计 Story、返回、内层 iframe 刷新均保留待办与设置。草稿在会话中保留。
- AC3：首次进入、场景切换、重置、外层刷新初始化；新窗口独立。越界选择留下保留状态；标注定位正确。
- AC4：固定候选和历史包可在子路径访问；切换 current 后旧窗口仍使用原完整包；Manager 和直接画布正常渲染。
- AC5：Plane 映射需求，源码提交产生预览，明确发起评审生成固定候选。Jacky 逐项通过后另行授权交付，合并后发布同包，评论重放不重复交付。原型完成不自动 Done。

## 示例范围

只有浏览器内模拟数据，无真实账号、服务器业务存储、消息推送或多用户任务协作。使用既有平台样式，无额外品牌设计。技术样例允许 Agent 构建与验证；人工审批不能代签。尚未逐项人工确认，不标记业务验收通过。

## BDD

```gherkin
功能: Storybook TodoList 技术验收
  场景: 跨应用与重挂载保持会话
    假如我在空白场景新增“验证固定包”
    当我完成该待办并在设置中关闭显示已完成
    那么列表中不再显示该待办
    当我重新开启显示已完成并切到统计 Story 再返回
    那么该待办仍为已完成且统计为一项
  场景: 单独授权后交付
    假如固定候选通过自动验证
    当真实评审人在 Plane 逐项通过
    那么尚不合并发布
    当该评审人单独授权交付
    那么合并并发布原确认完整包
```
